# Проверка продаж и совместимости JSON

Тесты используют только вымышленные данные. Рабочий JSON пользователя не нужен.

Проверка складской транзакции (Node.js):

```powershell
node --test --test-isolation=none tests/stock-service.test.cjs tests/project-file-service.test.cjs
```

Браузерная проверка реальных загрузчиков, интерфейса и сохранения:

```powershell
python -m http.server 18766 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:18766/tests/browser-check.html` и нажмите «Проверить на тестовых данных».
Используйте отдельный порт, на котором ранее не открывали рабочий проект: тест создаёт вымышленную старую копию в браузере, чтобы проверить, что она больше не загружается. Не подключайте к тестовой странице рабочий JSON.

Проверяются старые массивы, одиночные структурированные/HTML-снимки, книги v7/v8, поиск по неактивным листам, выбор дубликатов, продажа/оприходование, вызов звукового уведомления, откат при отказе подготовки данных, блокировки инвентаризации и повторное открытие JSON. Списание использует прежний тип движения `writeoff`, оприходование — `receipt`; версия экспорта остаётся 8. Цена не требуется.

Проверка переноса трёх листов и файлового режима: `http://127.0.0.1:18766/tests/json-browser-check.html` (запускается автоматически). Используются реальные функции таблицы и файловый объект в памяти: проверяются названия, данные, история, загрузка свежего файла при старте, отсутствие записи при открытии, несохранённые изменения, отмена открытия, отказ доступа, ошибки записи и конфликт с внешней версией файла. Отдельно проверяются скачивание JSON без File System Access и выгрузка старой копии браузера.

Автосохранение: проверяется интервал 300 000 мс (5 минут), сохранение при непрерывных изменениях, сохранение курсора в редакторе, отсутствие параллельных записей, переключение файлов, первый выбор файла, пауза при открытом диалоге, разрешения, отзыв доступа и повтор после ошибки. Таймер в браузерном тесте ускоряется до одной секунды; производственный код передаёт полный пятиминутный интервал. Рабочий таймер не откладывается каждым новым изменением. Кнопка «Новая база» отсутствует.

Автоматический запуск обеих браузерных проверок в отдельном временном профиле Edge (сервер должен работать):

```powershell
node tests/run-browser-check.cjs
node tests/run-browser-check.cjs 'http://127.0.0.1:18766/tests/browser-check.html?autorun=1'
node tests/run-browser-check.cjs 'http://127.0.0.1:18766/tests/resume-browser-check.html'
```

Настоящий диалог выбора файла и разрешения браузера требуют отдельной ручной проверки. В тестах они заменены файловыми объектами в памяти. Тесты не обещают защиту от аппаратного сбоя диска или одновременной внешней записи в последний момент фиксации файла.

Проверка последнего файла использует настоящий `FileSystemFileHandle` тестового JSON из OPFS отдельного браузерного профиля, его сохранение в IndexedDB и полную перезагрузку страницы. Это только источник тестовых данных: приложение не сохраняет пользовательскую базу в OPFS. Проверяются свежие данные после внешней замены файла, все листы и их имена, «Сохранить как…», миграция старой файловой ссылки, кнопка повторного разрешения, отсутствие подстановки старой базы при ошибке запоминания и имя последнего файла для браузеров с обычным File input. Истечение разрешения проверяется на управляемом файловом объекте.

Физический сканер и слышимость сигнала проверяются отдельно на рабочем компьютере. Сканер должен отправлять Enter после кода, а звук вкладки не должен быть выключен.
